# Known pitfalls

Symptom, cause and fix for traps this project has already hit. Read before touching the area named.

| Area    | Symptom                                                                                                                                   | Cause                                                                                                                                                                                                                             | Fix                                                                                                                                                                                                                                                |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Map     | A tap or click on a station selects the station next to it on a phone or a zoomed-out map                                                 | Station hit circles stay 30 px wide on screen, so below a scale of about 0.43 they overlap and the browser reports whichever circle was drawn last                                                                                | `stationAt` in `src/map/TransitMap.jsx` resolves the pointer with `nearestStation` (`src/map/hitTest.js`). Send any new pointer handler on a station through it instead of trusting the element that received the event                            |
| Map     | Clicks on stations and lines do nothing except close the station card                                                                     | Calling `setPointerCapture` when the pointer goes down makes the browser send the click to the map surface instead of the station or line under it                                                                                | `src/hooks/usePanZoom.js` captures the pointer only after a drag has moved 5 px. A press that ends where the map cannot hear it (over the panel, outside the window) is ended by the next mouse move that has no button held                       |
| Data    | Every test file fails while loading, with an error that starts `network.json:`                                                            | `assertNetwork` in `src/lib/network.js` checks the data when the app loads: known stations and lines, one arrival and one departure minute per stop, full fare tables                                                             | Fix the entry the message names. After a station change also update `STATION_LAYOUT` and `CORRIDORS` in `src/map/schematic.js` and `api/_lib/stop-parents.js`; `test/data.test.js` checks all three                                                |
| Alerts  | The alerts button says "unavailable" although `/api/alerts` answers with alerts                                                           | The app rejects the whole response when one alert is missing a field or has the wrong type (`assertAlertsPayload` in `src/lib/alerts.js`), so a half-read alert can never blank the page                                          | Change the shape in `api/_lib/alerts-feed.js` and in `assertAlertsPayload` together. `test/alerts-payload.test.js` feeds the function's real output through the check                                                                              |
| Reach   | Reach lists a one-seat ride with transfers, or disagrees with the trip planner on a route                                                 | The transfer slider used as the cost of boarding makes a change free at "none", and a second copy of the graph and search drifts from the planner's                                                                               | Both search `src/lib/graph.js` with one boarding cost, and `computeReach` adds the sliders to the planner's route afterwards. `test/planner-reach.test.js` compares the two on every station pair in every service                                 |
| Trips   | A chosen route option jumps back to the first one, and the route is read out again                                                        | The clock ticks every minute. Anything it feeds that gets a new object each tick (the service, a "Right now" answer) re-runs every effect keyed on it                                                                             | `App.jsx` keys on `serviceKey(service)`, and `sameWhileUnchanged` in `src/lib/graph.js` hands back the earlier "Right now" answer while it reads the same. `test/right-now.test.js` checks that                                                    |
| Trips   | "Right now" finds no train although BART still runs one                                                                                   | Only regular stopping patterns of the current period count. The day's few odd last trains, and evening trains while it is still before 9 pm, do not                                                                               | The panel says "No regular train still to come" and points to bart.gov and the other services. Lifting this needs a search over real departure times, not stopping patterns                                                                        |
| Data    | `npm test` and CI fail with "The schedule in src/data/network.json ends on ..." although nobody changed anything                          | `test/data.test.js` compares the end of the schedule's calendar with today's date and fails on purpose from 30 days before it                                                                                                     | Rebuild `network.json` (and `stop-parents.js` if platforms changed) from BART's current feed. Do not raise the limit or skip the test: after the end date the app tells riders the timetable has ended                                             |
| Tests   | A test that opens the app fails with `document is not defined`, hangs, or cannot click a station                                          | Tests run in plain Node unless the file starts with `// @vitest-environment jsdom`. jsdom has no layout, media queries, modal dialogs or canvas, and SVG elements have no `click()`                                               | Start the file with that comment and use `mount`, `click`, `pointer` and `advance` from `test/dom.js`, which also stands in for the missing browser features. Use fake timers and set the date first: the app reads the clock and polls for alerts |
| Alerts  | `/api/alerts` keeps answering 502, or an old copy marked stale, for a few seconds after BART is back                                      | After a failed call the function does not ask BART again for `FAILURE_BACKOFF_MS` (15 seconds), and callers that arrive together share one call. Both keep an outage from turning every visitor poll into a request to BART       | Expected. Tune the constants at the top of `api/alerts.js`; `test/alerts-api.test.js` counts the upstream calls. Do not add a code path that calls `readFeed` without going through `refresh`                                                      |
| Alerts  | A field BART adds to its alerts never reaches the app, or a test cannot encode it                                                         | `api/_lib/feed-message.js` reads the feed by field number and knows only the fields the app uses. The tests encode with protobufjs from the message list in `test/feed.js`                                                        | Add the field, with its number from gtfs-realtime.proto, to both files. An empty answer or one without a header is rejected on purpose, so a blank reply from BART is an outage and not "no alerts"                                                |
| Tooling | `npm audit` fails on minimatch after the `overrides` block is removed, or lint picks up or ignores different files after an eslint update | eslint 10.14.0 and @eslint/config-array 0.23.5 ask for minimatch 10, which sits inside an advisory's range (7.0.0 up to 11.0.1). `overrides` in `package.json` forces both onto minimatch 11, a major version they do not declare | On each eslint update, delete the `overrides` block on a branch and run `npm install --package-lock-only --ignore-scripts`, then `npm audit` and `npm ls minimatch`. Keep it deleted if the audit is clean; otherwise put it back                  |
